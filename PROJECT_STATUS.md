# Series Tracker — статус проекта

Дата актуальности: 2026-07-24 (конец сессии, упирающейся в лимит контекста).

Личный трекер сериалов (аналог Trakt.tv), многопользовательский, данные о сериалах берутся с TMDb на лету, своя БД хранит только личные отметки пользователей.

---

## 1. Общее состояние проекта

**Стек:**
- **Next.js 16.2.11** (App Router, Turbopack, TypeScript) — ⚠️ это не обычный Next.js, версия из будущего с breaking changes относительно того, что вы могли видеть раньше (см. `AGENTS.md` в корне — там прямое указание сверяться с `node_modules/next/dist/docs/` перед правками).
- **React 19.2.4**
- **Prisma 7.9.0** с провайдером **SQLite**, доступ через **`@prisma/adapter-libsql`** (не `better-sqlite3` — тот требует нативной компиляции, на этой машине нет Python/build tools, поэтому выбран libSQL-адаптер, не требующий сборки).
- **Auth.js (next-auth) v5 beta** — email+пароль (bcryptjs), JWT-сессии.
- Внешние API: **TMDb** (основной источник данных), **OMDb** (рейтинг IMDb), **kinopoiskapiunofficial.tech** (неофициальный API Кинопоиска).

## 2. Что уже реализовано и работает

### Авторизация
- Регистрация (`/register`): email + пароль + имя + фамилия, пароль хешируется bcrypt, автологин после регистрации.
- Вход (`/login`): email + пароль, понятные ошибки ("неверный email или пароль", "email уже занят" и т.д.).
- Middleware редиректит неавторизованных на `/login` для всех страниц кроме `/`, `/login`, `/register`.
- Протестировано вживую через curl (эмуляция форм) — регистрация, вход, изоляция данных между двумя разными аккаунтами — всё подтверждено.

### Главная страница (`/`)
- Публичная (доступна без входа).
- Приглушённый цветной градиент на фоне всего сайта, меняющий оттенок при скролле (`ScrollGradient.tsx` + CSS-переменная `--scroll-progress`).
- По центру — карточка входа/регистрации (или "Перейти в библиотеку" + имя, если уже вошли).
- Вокруг — 12 "конвейерных" колонок постеров популярных сериалов (TMDb `/tv/popular`), едут снизу вверх бесконечно, у каждой свой сдвиг по времени.
- Полностью реализовано и одобрено пользователем.

### Поиск (`/search`)
- Простой поиск по TMDb (`/search/tv`), сетка результатов постер+название+год.
- Работает, отдельно не дорабатывался в последних сессиях (базовый MVP-вариант).

### Страница сериала (`/series/[id]`) — самая проработанная часть
- Постер (фикс. высота 420px), заголовок, диапазон лет ("2023–нв" если идёт, "2020–2023" если завершён, просто год если начался/закончился в один год), жанры (переведены, "Sci-Fi" вместо "НФ и Фэнтези" для id 10765), счётчик "X/30 серий" — X считается по реальным отметкам "просмотрено".
- Бейджи рейтингов в ряд: IMDb (через OMDb API), Кинопоиск (через неофициальный API, сверка по `imdbId` для точного совпадения сериала), **рейтинг сайта** — среднее по звёздам, которые поставили ВСЕ пользователи именно этого сайта (не TMDb-данные), с количеством оценивших.
- Трейлер — встроенный YouTube iframe, TMDb `/videos`, приоритет: официальный русский → любой русский → официальный английский → любой → тизер.
- Вертикальный виджет "10 звёзд" вдоль правого края постера — свой личный рейтинг пользователя, с половинками (клик по нижней половине звезды = X.5, по верхней = X.0), заливка идёт снизу вверх. Сохраняется через server action `setRating`, оптимистичное обновление UI.
- Блок "Сезоны" — кликабельные цифры-вкладки (стиль Amediateka), при заходе на страницу автоматически открывается **первый сезон с непросмотренными сериями** (если всё просмотрено — открывается последний сезон).
- Ряд эпизодов (`EpisodeRow.tsx`) — карточки 8 в ряд, кадр + хронометраж (стеклянный бейдж), при наведении карточка увеличивается (scale 1.13) и появляется полупрозрачный глазик — клик реально сохраняет отметку "просмотрено" в БД (`toggleEpisodeWatched`), с оптимистичным откликом. Стрелки "вперёд/назад" — плавающие кнопки-стекло, привязаны к самой крайней миниатюре (не сдвигают вёрстку). Невышедшие серии (сравнение `air_date` с текущей датой) — серый фон "Скоро выходит" в две строки, без глазика и хронометража.
- Выбор фона страницы (`BackgroundPicker.tsx`) — галерея backdrop-кадров из TMDb внизу страницы, клик применяет затемнённый фон **только для этого сериала лично у этого пользователя** (поле `Series.backgroundPath`).
- "Убрать из библиотеки" — кнопка снизу.

### Моя библиотека (`/library`)
- Список отслеживаемых сериалов, читает данные **только из своей БД** (без обращения к TMDb) — специально сделано, чтобы страница работала даже без VPN/доступа к TMDb (изначально была проблема: без VPN TMDb недоступен, библиотека была пустой; исправлено кэшированием name/posterPath/year прямо в таблице `Series` при сохранении отметки).
- Фильтр по статусу (вкладки Все/Смотрю/В планах/Просмотрено/Брошено) — ⚠️ см. раздел 3, статус сейчас нигде не устанавливается.

### Общий дизайн
- Тёмная тема, фиолетово-розовый акцент, "стеклянные" (backdrop-blur) бейджи вместо сплошных чёрных плашек, многослойные тени/неоновая подсветка у постеров и заголовков для эффекта объёма.
- Ширина основного контейнера сайта увеличена (960px → 1320px), явно вырывается из общего контейнера через full-bleed трюк на странице сериала (отступы 4.5см слева/справа).

## 3. Что в процессе / не доделано

1. ~~Статус просмотра не устанавливается~~ — **решено в коммите `094f943`**: `Series.status` теперь считается автоматически при отметке серии просмотренной (0 просмотрено → `PLANNED`, часть → `WATCHING`, все → `COMPLETED`). Заодно исправлен смежный баг: раньше `toggleEpisodeWatched` вообще не создавал запись `Series`, поэтому сериал появлялся в библиотеке только после оценки/выбора фона — теперь запись создаётся сразу при первой отметке просмотра. Статус `DROPPED` больше нигде не выставляется (авто-вычислить его нельзя), поэтому вкладка "Брошено" убрана из фильтра библиотеки; сам enum-значение в схеме оставлено на будущее.
2. Поля `currentSeason`/`currentEpisode` в модели `Series` по-прежнему никто не пишет — дохлые колонки, реальный прогресс считается через `WatchedEpisode`. Можно оставить как есть или почистить схему отдельным шагом.
3. Три варианта расположения виджета звёзд делались специально для A/B-выбора пользователя — оставлен только "вертикально вдоль постера", код двух других вариантов уже удалён из `page.tsx`.
4. `public/popcorn.png` загружен, но не используется нигде в текущей вёрстке (эксперимент с попкорн-баннером на главной был отменён пользователем как "выглядит не очень").
5. Деплой на реальный хостинг **не делался** — сайт работает только на localhost. Обсуждали Railway (без переделок, т.к. persistent disk) vs Vercel+Turso (serverless, нужно менять БД) — пользователь пока отложил этот вопрос ("давай оставим это, будем работать локально").
6. Git-репозиторий: коммит `094f943` содержит все наработки прошлой сессии (звёзды-половинки, удаление старой формы, общий рейтинг сайта, выбор фона) плюс авто-статус из этой сессии.
7. Push в удалённый репозиторий (GitHub и т.п.) не делался — история существует только локально на диске пользователя.

### Известные технические нюансы (важно помнить)
- **Turbopack на этой Windows-машине периодически падает** с ошибкой `Jest worker encountered N child process exceptions` — не связано с кодом, чинится полным `taskkill //F //IM node.exe` + `rm -rf .next` + новый `npm run dev`. Уже случалось несколько раз за сессию.
- **DNS на этой машине резолвит внешние домены (TMDb, OMDb, Кинопоиск) в 127.0.0.1** — реальный выход в интернет только через VPN-прокси пользователя (`127.0.0.1:10809`, задан в `.env` как `HTTP_PROXY`/`HTTPS_PROXY`). Без активного VPN у пользователя эти обращения не пройдут вообще — библиотека при этом всё равно работает (не завязана на TMDb, см. п. "Моя библиотека" выше).
- **Браузерный инструмент (Claude_Browser preview) в этой среде сидит в отдельном сетевом пространстве (Docker-подобном) БЕЗ доступа к прокси пользователя** — поэтому для проверки страниц с обращением к TMDb использовался `curl` через Bash-инструмент (у него есть доступ к прокси), а не браузерный preview. Учитывать при верификации UI в новой сессии.
- Все запросы к TMDb/OMDb/Кинопоиску идут с `cache: "no-store"` — свежие данные при каждом заходе, никакого кэширования на нашей стороне (важно для актуальности дат выхода серий).
- Папка проекта на диске содержит **пробел в имени** (`series-tracker WEBSITE`) — переименовать не удалось (сам процесс Claude Code держит папку открытой), при работе с путями это учтено (относительные пути типа `file:./prisma/dev.db`, а не абсолютные с пробелом).

## 4. Ключевые технические решения

### TMDb API
- Клиент: `src/lib/tmdb.ts`. Токен — `TMDB_API_READ_ACCESS_TOKEN` (v4 auth, длинный JWT-подобный токен, НЕ короткий API key) в `.env`, уже заполнен и рабочий.
- Все запросы идут с `language=ru-RU` по умолчанию (переопределяется точечно, например для трейлеров).
- Ключевые функции: `searchSeries`, `getSeriesDetails`, `getPopularSeries`, `getSeriesTrailerKey`, `getSeasonEpisodes`, `getSeriesExternalIds`, `getSeriesBackdrops`, `tmdbImageUrl`, `seriesStatusLabel` (перевод статусов), `genreLabel` (переопределение "Sci-Fi" вместо "НФ и Фэнтези").
- Требуется прокси (см. раздел 3) — настроен через `HTTPS_PROXY`/`HTTP_PROXY` в `.env` + `src/instrumentation.ts` (регистрирует глобальный `ProxyAgent` из `undici` при старте Node-рантайма).

### OMDb API (рейтинг IMDb)
- `src/lib/omdb.ts`, ключ `OMDB_API_KEY` в `.env` (бесплатный тариф, 1000 запросов/день), уже заполнен и рабочий.
- IMDb ID сериала берём через `getSeriesExternalIds` (TMDb `/external_ids`), затем запрос к OMDb по этому ID.

### Кинопоиск (неофициальный API)
- `src/lib/kinopoisk.ts`, ключ `KINOPOISK_API_KEY` в `.env`, уже заполнен и рабочий.
- Прямого поиска по IMDb ID нет — поэтому: ищем по названию (`search-by-keyword`), берём топ-5 кандидатов, для каждого запрашиваем полную карточку (`/films/{id}`) и сверяем её `imdbId` с нашим — совпадение подтверждает, что это тот же сериал. Если совпадений нет — рейтинг просто не показывается (без ложных срабатываний).

### База данных (Prisma + SQLite через libSQL)
```prisma
model User {
  id, email (unique), passwordHash, firstName, lastName, createdAt
  → series: Series[], watchedEpisodes: WatchedEpisode[]
}

model Series {
  id, userId, tmdbId
  name, posterPath, year          — кэш данных TMDb (чтобы библиотека работала без VPN)
  status (enum, см. известную проблему выше), currentSeason, currentEpisode  — сейчас не пишутся
  rating (Float?)                  — личная оценка звёздами, с половинками
  backgroundPath (String?)         — выбранный фон для страницы этого сериала у этого юзера
  createdAt, updatedAt
  @@unique([userId, tmdbId])
}

model WatchedEpisode {
  id, userId, tmdbId, seasonNumber, episodeNumber, watchedAt
  @@unique([userId, tmdbId, seasonNumber, episodeNumber])
}
```
- 7 миграций применены, БД в актуальном состоянии.
- Подключение через `@prisma/adapter-libsql`, URL `file:./prisma/dev.db` (**обязательно относительный путь** — абсолютный путь с пробелом в имени папки ломает парсинг URL внутри libsql, это была причина серьёзного бага в начале проекта).

### Нестандартные решения, которые стоит помнить
- **Server Actions вызываются напрямую из клиентских компонентов** (не только через `<form action={...}>`) — например, `toggleEpisodeWatched`, `setRating`, `setSeriesBackground` вызываются прямо в `onClick` с обычными аргументами (не `FormData`), с оптимистичным обновлением локального `useState` и откатом при ошибке через `.catch()`.
- Смена сезона в `TrackingForm` использует `key={season}` на `<EpisodeRow>`, чтобы React полностью пересоздавал компонент и сбрасывал внутреннюю пагинацию при переключении сезона (без этого пагинация "утекала" между сезонами).
- Middleware разделён на `auth.config.ts` (edge-safe, без Prisma/bcrypt) и `auth.ts` (полный, с провайдером) — иначе Prisma-клиент не собирается в edge-рантайме `middleware.ts`.
- Экспорт `middleware.ts` обязательно как `export default auth` — деструктуризация с переименованием (`export const { auth: middleware } = ...`) не распознаётся Next.js статическим анализатором и ломает обработку запросов (реальный баг, который был найден и исправлен).

## 6. Как запустить проект

```bash
cd "D:\Programms\series-tracker WEBSITE"
npm run dev
```
Открыть: `http://localhost:3000`

**Все переменные окружения в `.env` уже заполнены и рабочие**, ничего дополнительно настраивать не нужно:
- `DATABASE_URL` — путь к SQLite-файлу (уже правильный, не трогать формат).
- `AUTH_SECRET` — секрет для подписи JWT-сессий.
- `HTTPS_PROXY` / `HTTP_PROXY` — прокси для выхода в интернет с этой машины (нужен VPN пользователя включённым, иначе TMDb/OMDb/Кинопоиск будут недоступны — но библиотека и вся остальная навигация по сайту при этом продолжат работать).
- `TMDB_API_READ_ACCESS_TOKEN`, `OMDB_API_KEY`, `KINOPOISK_API_KEY` — ключи трёх внешних API, все настоящие и рабочие.

**Если после git pull / переустановки нужно поднять БД с нуля:**
```bash
npx prisma migrate deploy
npx prisma generate
```

**Если Turbopack начинает выдавать непонятные ошибки (`Jest worker...`, `Failed to find Server Action` и т.п.):**
```bash
taskkill //F //IM node.exe
rm -rf .next
npm run dev
```
