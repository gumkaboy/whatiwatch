## 2. КРИТИЧЕСКИ ВАЖНЫЙ технический нюанс — миграции Prisma и Turso

**`prisma migrate deploy` / `migrate status` НЕ РАБОТАЮТ напрямую с `libsql://` URL** (ошибка `P1013: The provided database string is invalid`). Это ограничение самого Prisma 7 CLI — миграционный движок не понимает схему `libsql://`, драйвер-адаптер работает только в рантайме приложения (`PrismaClient`), не в CLI.

**Как накатывать новую миграцию на Turso** (пошагово, проверено рабочим способом):

1. Как обычно: `npx prisma migrate dev --name имя_миграции` — создаёт папку в `prisma/migrations/` и применяет к ЛОКАЛЬНОЙ базе.
2. Написать одноразовый скрипт (например `scratch-apply-migration.mjs` в корне проекта, удалить после использования), который:
   - подключается к Turso через `@libsql/client` (`createClient({ url, authToken })`, значения брать из `.env`/Vercel);
   - читает `migration.sql` из новой папки миграции;
   - выполняет его через `client.executeMultiple(sql)`;
   - **обязательно** добавляет запись в служебную таблицу `_prisma_migrations` (иначе Prisma не будет знать, что миграция применена):
     ```sql
     INSERT INTO "_prisma_migrations"
       (id, checksum, finished_at, migration_name, applied_steps_count, started_at)
       VALUES (?, ?, CURRENT_TIMESTAMP, ?, 1, CURRENT_TIMESTAMP)
     ```
     где `checksum` = `sha256(migration.sql содержимое)` в hex, `id` = случайный UUID.
3. Запустить скрипт с переменными окружения Turso, удалить скрипт.

Таблица `_prisma_migrations` на Turso создана вручную с классической Prisma-схемой (id TEXT PK, checksum TEXT, finished_at DATETIME, migration_name TEXT, logs TEXT, rolled_back_at DATETIME, started_at DATETIME, applied_steps_count INTEGER).

Локально для быстрых точечных правок в БД (создать/удалить тестового юзера, проверить статус) удобно использовать `node:sqlite` (встроен в Node 22+/24) напрямую на `prisma/dev.db`, без похода в Prisma Client — быстрее для одноразовых scratch-запросов.

## 3. Почему падал деплой на Vercel (если снова начнёт падать с той же ошибкой)

Три часа убили на дебаг ошибки `npm error Exit handler never called!` при `npm install`/`npm ci` на Vercel.

**Настоящая причина**: в Vercel через "Import .env" затянулись переменные `HTTPS_PROXY`/`HTTP_PROXY` (это костыль ТОЛЬКО для локальной машины разработчика — там DNS резолвит внешние домены в 127.0.0.1, нужен VPN-прокси на `127.0.0.1:10809`). `npm` на сервере Vercel подхватил эти переменные и пытался качать пакеты через несуществующий на сервере прокси → `ECONNREFUSED`.

**Фикс**: удалить `HTTPS_PROXY`/`HTTP_PROXY` из Environment Variables в Vercel. Если в новой сессии Vercel снова начнёт падать похожим образом — первым делом проверить, не появились ли там снова эти две переменные.

## 4. Что реализовано (полный список, включая эту сессию)

### Авто-статус просмотра
- `Series.status` считается автоматически по количеству просмотренных серий (0 → "Хочу посмотреть", часть → "Смотрю", все **вышедшие** → "Просмотрено").
- Кнопка-иконка 🔖 — сохранить в библиотеку (toggle). Кнопка-иконка 👁 — отметить все вышедшие серии просмотренными разом (toggle). Не вышедшие серии никогда не отмечаются просмотренными автоматически.

### Библиотека — статистика
- 4 круга (стеклянный стиль): число сериалов ("Смотрю"+"Просмотрено"), просмотренных серий, часов, дней (по кэшированному `WatchedEpisode.runtime`).

### Комментарии
- Плоский список под каждым сериалом, сортировка от новых к старым, удаление только своих.

### Профиль пользователя
- `/profile`: имя, фамилия, город, дата рождения, email (read-only), смена пароля.

### Восстановление пароля — **полностью готово**
- `/forgot-password` → email → токен (`PasswordResetToken`, 1 час) → `/reset-password`.
- Домен `whatiwatch.ru` **верифицирован в Resend** (DKIM/SPF/MX/DMARC записи добавлены в DNS-зоне на reg.ru), `RESEND_FROM_EMAIL="whatiwatch <noreply@whatiwatch.ru>"` задан в Vercel. Письма реально доходят любым пользователям, не только владельцу аккаунта Resend.
- Без `RESEND_API_KEY` (локально) ссылка на сброс пишется в консоль сервера — это осознанный dev-fallback.

### Вход/регистрация — модалка на главной странице
- Убраны отдельные "Вход"/"Регистрация" из шапки для гостей — шапка вообще не рендерится для неавторизованных (там всё равно было бы пусто).
- Кнопки "Войти"/"Зарегистрироваться" на лендинге открывают модалку на этой же странице (`src/components/AuthButtons.tsx`), без перехода на `/login`/`/register`.
- ⚠️ Модалка рендерится через `createPortal` в `document.body` — обязательно, т.к. `.landing-center` (родитель) имеет `transform: translateX(-50%)`, что создаёт новый containing block для `position: fixed` — без портала модалка масштабировалась и позиционировалась относительно маленького родительского блока, а не всего экрана.
- Выход из аккаунта (`signOutAction`) редиректит на `/` (лендинг с постерами), не на `/login`.

### Главная страница (лендинг для гостей, `/`)
- Название сайта — **whatiwatch**.
- Логотип: "w" + оригинальный значок (кроп `free-png-cropped.png` — обрезаны прозрачные поля вокруг видимого рисунка, иначе при растягивании box'а прозрачные поля растягивались вместе с рисунком и создавали невидимый "лишний" отступ) + "w". Финальные пропорции и отступы (1см до текста, положение по вертикали и т.д.) — см. `.landing-center`/`.brand-title`/`.brand-icon` в `globals.css`.
- Карусель постеров ("кирпичная кладка"): свой список `src/lib/curatedSeries.ts` (~107 тайтлов). Бесшовный луп (контент задвоен, `-50%` от **реальной** высоты контента, трек `height: auto`). Для гостей карусель занимает весь экран (0 до низа вьюпорта, шапка не рендерится); для залогиненных, если попадают на `/` — шапка есть, высота карусели = `calc(100vh - 3.25rem)`.

### Главный дашборд для залогиненных — `/home` ("Главная" в шапке, самая левая ссылка)
Новая страница с двумя живыми подборками:
1. **"Продолжить просмотр"** — сериалы из библиотеки, у которых отмечена хотя бы одна серия, сортировка по дате последнего просмотра. Исключены статусы `DROPPED` всегда; для `COMPLETED` делается **живая проверка через TMDb** (см. ниже) — если по факту вышли новые неотмеченные серии, сериал возвращается в подборку, несмотря на устаревший статус в БД.
2. **"Популярное"** — живые данные из **Trakt API** (`shows/popular`), резолвится в постеры/названия через TMDb, кэш на 1 час (`next: { revalidate: 3600 }`).

Обе секции используют общий компонент `src/components/PosterCarouselRow.tsx`: непрерывная авто-прокрутка (JS `setInterval`, НЕ CSS-анимация и НЕ `requestAnimationFrame` — см. технический нюанс ниже) + ручные стрелки влево/вправо, которые временно приостанавливают авто-скролл на время своей анимации. Если элементов мало и весь ряд помещается без скролла — рендерится статично, без стрелок и без дублирования тайлов (double-render только когда реально нужен бесшовный луп).

Строка поиска по центру наверху (`<form action="/search">`, обычный GET) — ссылка "Поиск" из шапки убрана как избыточная.

### Дизайн страницы сериала
- Постер: тонкий неоновый контур на странице сериала (не диффузный blur).
- Звёзды — колонка справа от постера.
- Иконки 🔖/👁 — выровнены по baseline заголовка.
- Просмотренные серии — темнее через `filter: brightness()` (не `opacity`).
- Логотип канала/платформы — над строкой год/жанр (`networks[0].logo_path`).
- Трейлер — YouTube iframe, приоритет: ru сезон 1 → ru любой → en сезон 1 → en любой. YouTube сам может быть недоступен без VPN — не наша инфраструктура, видео-прокси не делали.

### Картинки — прокси через собственный сервер
- `/api/tmdb-image` (`src/app/api/tmdb-image/route.ts`) — сервер сам качает картинку с TMDb, отдаёт со своего домена (у части пользователей без VPN `image.tmdb.org` заблокирован на уровне сети).
- Этот роут обязательно исключён из auth-проверки в `src/proxy.ts` (matcher включает `api/tmdb-image`).

## 5. Технические нюансы, найденные за эту сессию (важно помнить)

1. **`requestAnimationFrame` ненадёжен в headless/непроявленных вкладках** — при автотестировании через собственный превью-браузер (когда панель браузера физически не отображается/не композится) `rAF`-коллбэки почти никогда не тикают, а вот `setInterval` — тикает стабильно, просто может подтормаживать по таймингу. Поэтому вся анимация каруселей на `/home` сделана через `setInterval`, а не `rAF` и не CSS/нативный `scrollBy({behavior:"smooth"})` (последний тоже не давал эффекта в тесте — возможно, по той же причине, связанной с композитингом). Подтверждено рабочим на реальном проде через настоящий Chrome пользователя.
2. **CSS: `overflow-x: auto` без явного `overflow-y` автоматически делает `overflow-y: auto` тоже** (спека CSS Overflow) — из-за этого transform:scale() на постере при наведении обрезался по вертикали контейнером-каруселью. Фикс — не пытаться выставить `overflow-y: visible` (спека всё равно приведёт его к `auto`), а дать контейнеру достаточный вертикальный `padding`, чтобы увеличенная плитка физически помещалась и не "переполняла" бокс.
3. **Flexbox: элементу с `flex: 1` и `overflow-x: auto` внутри (карусельный трек) обязательно нужен `min-width: 0`** — иначе по умолчанию `min-width: auto` не даёт элементу сжаться меньше суммарной ширины контента, из-за чего проверка переполнения (`scrollWidth > clientWidth`) всегда врёт, что контент помещается, даже когда явно не помещается.
4. **Trakt API отдаёт 403 без реалистичного `User-Agent`** — Cloudflare перед `api.trakt.tv` блокирует server-to-server fetch без браузерного UA (проверено: и с локальной машины, и с самого Vercel — не проблема IP/прокси, просто нужен заголовок вида `Mozilla/5.0 ... Chrome/120.0.0.0 ...`). См. `src/lib/trakt.ts`.
5. **PNG с прозрачными полями и `object-fit: fill`** — если у декоративной картинки есть прозрачные отступы вокруг видимого рисунка, при растягивании контейнера эти отступы растягиваются вместе с рисунком и превращаются в реальный (хоть и невидимый) визуальный зазор, который не отследить через `getBoundingClientRect()` на самом элементе. Нужно обрезать картинку по фактической bounding box непрозрачных пикселей (можно посчитать через `sharp` + разбор alpha-канала) перед тем как полагаться на её размеры в вёрстке.
6. Papka проекта содержит пробел в имени (`series-tracker WEBSITE`) — использовать относительные пути/кавычки.
7. Локальная машина: DNS резолвит внешние домены в 127.0.0.1, нужен VPN пользователя + `HTTPS_PROXY`/`HTTP_PROXY` в `.env` для доступа к TMDb/OMDb/Кинопоиску/Trakt. **Это ТОЛЬКО для локальной разработки, никогда не переносить эти переменные в Vercel.**
8. Кинопоиск API: лимит 500 запросов/день. OMDb: лимит 1000/день. Trakt: 1000 GET/5 минут даже без авторизации — с нашим кэшем на 1 час более чем достаточно.
