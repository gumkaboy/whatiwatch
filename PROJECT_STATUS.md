## 2. КРИТИЧЕСКИ ВАЖНЫЙ технический нюанс — миграции Prisma и Turso

**`prisma migrate deploy` / `migrate status` НЕ РАБОТАЮТ напрямую с `libsql://` URL** (ошибка `P1013: The provided database string is invalid`). Это ограничение самого Prisma 7 CLI — миграционный движок не понимает схему `libsql://`, драйвер-адаптер работает только в рантайме приложения (`PrismaClient`), не в CLI.

**Как накатывать новую миграцию на Turso** (пошагово, проверено рабочим способом за эту сессию):

1. Как обычно: `npx prisma migrate dev --name имя_миграции` — создаёт папку в `prisma/migrations/` и применяет к ЛОКАЛЬНОЙ базе.
2. Написать одноразовый скрипт (например `scratch-apply-migration.mjs` в корне проекта, удалить после использования), который:
   - подключается к Turso через `@libsql/client` (`createClient({ url, authToken })`, значения брать из `.env`/Vercel);
   - читает `migration.sql` из новой папки миграции;
   - выполняет его через `client.executeMultiple(sql)`;
   - **обязательно** добавляет запись в служебную таблицу `_prisma_migrations` (иначе Prisma не будет знать, что миграция применена):
     ```sql
     INSERT INTO "_prisma_migrations"
       (id, checksum, finished_at, migration_name, applied_steps_count, started_at)
       VALUES (?, ?, CURRENT_TIMESTAMP, ?, 1, CURRENT_TIMESTAMP)
     ```
     где `checksum` = `sha256(migration.sql содержимое)` в hex, `id` = случайный UUID.
3. Запустить скрипт с переменными окружения Turso, удалить скрипт.

Таблица `_prisma_migrations` на Turso создана вручную с классической Prisma-схемой (id TEXT PK, checksum TEXT, finished_at DATETIME, migration_name TEXT, logs TEXT, rolled_back_at DATETIME, started_at DATETIME, applied_steps_count INTEGER).

## 3. Почему падал деплой на Vercel (если снова начнёт падать с той же ошибкой)

Три часа убили на дебаг ошибки `npm error Exit handler never called!` при `npm install`/`npm ci` на Vercel. Перепробовали: смену Node.js версии (24.x→22.x), `--ignore-scripts`, фиксацию версии npm — ничего не помогало, падало стабильно на ~70-й секунде.

**Настоящая причина**: в Vercel через "Import .env" затянулись переменные `HTTPS_PROXY`/`HTTP_PROXY` (это костыль ТОЛЬКО для локальной машины разработчика — там DNS резолвит внешние домены в 127.0.0.1, нужен VPN-прокси на `127.0.0.1:10809`). `npm` на сервере Vercel подхватил эти переменные и пытался качать пакеты через несуществующий на сервере прокси → `ECONNREFUSED`.

**Фикс**: удалить `HTTPS_PROXY`/`HTTP_PROXY` из Environment Variables в Vercel. Install Command можно оставить дефолтным (`npm ci`). Если в новой сессии Vercel снова начнёт падать похожим образом — первым делом проверить, не появились ли там снова эти две переменные.

**Важно**: у сервера в облаке (Vercel) обычный доступ в интернет, прокси ему не нужен вообще — только у локальной машины пользователя есть эта особенность сети.

## 4. Что реализовано за эту сессию (полный список)

### Авто-статус просмотра
- `Series.status` считается автоматически по количеству просмотренных серий (0 → "Хочу посмотреть", часть → "Смотрю", все **вышедшие** → "Просмотрено").
- ⚠️ Пофикшен баг: статус "Просмотрено" раньше сравнивался с ОБЩИМ числом серий сериала (`series.number_of_episodes`, включая ещё не вышедшие анонсированные серии) — из-за этого идущие сериалы никогда не могли получить статус "Просмотрено". Теперь сравнивается с количеством **реально вышедших** серий (`air_date <= сегодня`).
- Кнопка-иконка 🔖 рядом с названием — сохранить в библиотеку как "Хочу посмотреть" (toggle, повторный клик убирает).
- Кнопка-иконка 👁 рядом с названием — отметить **все вышедшие** серии просмотренными за раз (toggle: повторный клик снимает отметки). Ещё не вышедшие серии никогда не помечаются просмотренными автоматически — это гарантировано и проверено.

### Библиотека — статистика
- Над списком сериалов — 4 круга (в стеклянном стиле): сколько сериалов (только "Смотрю"+"Просмотрено", не считая "Хочу посмотреть"), сколько серий просмотрено (глобально, только реально вышедшие — структурно гарантировано, т.к. непоказанные серии физически не могут попасть в таблицу просмотренных), сколько часов, сколько дней.
- Хронометраж (`WatchedEpisode.runtime`) кэшируется в момент отметки просмотра — у серий, отмеченных **до** этого обновления, runtime = null, они не дают вклада в часы/дни, пока их не переотметить.

### Комментарии
- Плоский список комментариев под каждым сериалом (`Comment` модель), сортировка от новых к старым, удаление только своих.

### Профиль пользователя
- `/profile` (открывается кликом по имени в шапке): имя, фамилия, город, дата рождения (редактируются), email (только просмотр), смена пароля.

### Восстановление пароля
- `/forgot-password` → email → токен (`PasswordResetToken`, живёт 1 час) → `/reset-password` → новый пароль.
- Письма шлются через Resend. **⚠️ Домен whatiwatch.ru в Resend ещё НЕ верифицирован** — пока реальные письма уходят только на собственный email аккаунта Resend, не на email обычных пользователей. Чтобы заработало по-настоящему: зайти в Resend → Domains → Add Domain → `whatiwatch.ru` → прописать выданные DNS-записи (TXT/DKIM) в панели reg.ru.
- Без `RESEND_API_KEY` (например, локально в dev) ссылка на сброс просто пишется в консоль сервера — так и задумано, реальный fallback для разработки.

### Дизайн страницы сериала
- Постер: свечение — тонкий контурный неон (не диффузный blur), только на странице сериала, отдельно от карточек в библиотеке/поиске.
- Звёзды — вертикальная колонка справа от постера, размер и отступы подобраны под геометрию постера.
- Иконки 🔖/👁 — одинакового размера, выровнены по нижней границе строчных букв заголовка (через `align-items: baseline`).
- Просмотренные серии — темнее (через `filter: brightness()`, НЕ через `opacity` — это принципиально: opacity делает прозрачным и сквозь миниатюру видно фон страницы, что выглядит как баг).
- Логотип канала/платформы (Netflix, HBO и т.д.) — над строкой год/жанр, через `networks[0].logo_path`.
- Трейлер — YouTube iframe, приоритет: русский трейлер 1-го сезона → любой русский → английский трейлер 1-го сезона → любой английский трейлер сериала. ⚠️ Известное ограничение: сам YouTube может быть недоступен части пользователей без VPN — это НЕ то же самое, что проблема с картинками (см. ниже), полноценного решения нет (video-прокси не реализовывали, обсуждали и отложили).

### Картинки — прокси через собственный сервер
- Раньше постеры грузились браузером пользователя напрямую с `image.tmdb.org` — у части пользователей без VPN (похоже, в России) этот CDN заблокирован на уровне сети, картинки не грузились.
- Сделан свой роут `/api/tmdb-image` (`src/app/api/tmdb-image/route.ts`) — сервер сам качает картинку с TMDb и отдаёт пользователю с своего домена. `tmdbImageUrl()` в `src/lib/tmdb.ts` теперь возвращает ссылку на этот прокси, а не на TMDb напрямую.
- ⚠️ Этот роут обязательно должен быть исключён из auth-middleware (`src/middleware.ts`, matcher включает `api/tmdb-image`) — иначе гости на главной странице (постеры без входа) получат HTML страницы логина вместо картинки.

### Главная страница
- Название сайта — **whatiwatch** (было "Series Tracker").
- Логотип: буквы "w" + свой оригинальный SVG-значок восклицательного знака (НЕ png с pngwing — тот был точной копией персонажа-маскота Pixar "Luxo Jr.", отказался использовать по правам, объяснил пользователю, нарисовал свой знак с нуля) + "w". Иконка примерно в 1.7 раза выше букв (пропорция вычислена по макету пользователя). Все элементы идут одним flex-потоком (заголовок → текст → карточка входа) без абсолютного позиционирования по процентам — раньше это вызывало наложение элементов друг на друга при увеличении размера логотипа.
- Конвейер постеров ("кирпичная кладка"): список сериалов — свой, подобранный вручную (`src/lib/curatedSeries.ts`, ~107 тайтлов с id+posterPath, статические данные, без обращения к TMDb на каждый заход — работает даже без VPN). Анимация — бесшовный луп (контент дублирован дважды, крутится на -50% от РЕАЛЬНОЙ высоты контента — важно: у анимируемого внутреннего трека height ДОЛЖЕН быть `auto`, а не фиксированный, иначе -50% считается от неправильной величины и цикл дёргается/видны "прыжки" контента). Кирпичное смещение колонок — чередование двух фаз (0 и пол-плитки), все колонки с ОДНОЙ и той же скоростью (иначе кладка со временем расползается).
- Страницы входа/регистрации/восстановления пароля — стеклянный стиль (blur+полупрозрачность), в общем духе сайта.

## 5. Что НЕ сделано / отложено

1. **Верификация домена в Resend** — см. раздел про восстановление пароля выше. Первое, что стоит сделать в новой сессии, если пользователь спросит про письма.
2. **Главная страница с подборками по жанрам/категориям** — из исходного списка идей пользователя (профиль ✅, восстановление пароля ✅, подборки на главной ❌, подписки на пользователей ❌ отложено намеренно). Сейчас на главной только конвейер постеров, не полноценные тематические подборки.
3. **Подписки на пользователей / лента "что смотрят друзья"** — пользователь сам предложил отложить, пока не наберётся реальная база активных пользователей.
4. **Видео-прокси для трейлеров** — обсуждали, не делали (сложнее, чем прокси картинок; сам YouTube может быть недоступен без VPN — фундаментальное ограничение, не наша инфраструктура).
5. Deep-review логотипа на главной — в конце сессии несколько раз итерировали размеры/пропорции по скетчам пользователя, последняя версия финализирована и задеплоена, но стоит переспросить пользователя, всё ли устраивает на свежий взгляд.

## Известные технические нюансы (по-прежнему актуальны)
- Papka проекта содержит пробел в имени (`series-tracker WEBSITE`) — использовать относительные пути.
- Локальная машина: DNS резолвит внешние домены в 127.0.0.1, нужен VPN пользователя + `HTTPS_PROXY`/`HTTP_PROXY` в `.env` для доступа к TMDb/OMDb/Кинопоиску. **Это ТОЛЬКО для локальной разработки, никогда не переносить эти переменные в Vercel** (см. раздел 3).
- Turbopack на Windows периодически падает (`Jest worker encountered N child process exceptions`) — чинится `taskkill //F //IM node.exe` + `rm -rf .next` + `npm run dev`.
- Кинопоиск API: бесплатный лимит 500 запросов/день — исчерпывается очень быстро даже при тестировании вдвоём, при реальном трафике рейтинг Кинопоиска будет часто не показываться (это ожидаемо, не баг).
- OMDb: бесплатный лимит 1000 запросов/день — тоже может не хватать при росте трафика.
